# Full-repository audit — 2026-08-09

An autonomous `/audit-code` run over the whole repo (141 files, 172 components, 111 analysis units,
1298 dependency edges). It produced **676 findings across 111 work blocks** — 59 high, 445 medium,
171 low. Raw output is **not** in git: `.audit-tools/audit-report.md` (1.3 MB),
`.audit-tools/audit-findings.json` (2.4 MB), `.audit-tools/audit-verification-note.md`.

⚠ **Every finding was authored by the Codex offload lane (`gpt-5.6-sol`), which is advisory by
project rule — not a conclusion.** Of the 676, **6 were verified against source and 4 are confirmed
defects**. The other 670, including 58 of the 59 highs, are **unverified**; their severity and
confidence are the authoring model's own estimates. This document records only what was verified.
Nothing here is fixed yet.

## Open — confirmed defects

### 1. `argValue()` re-reads an option's VALUE as a flag

`src/cli.ts:62-73`. The scan walks every `process.argv` token and returns `argv[i+1]` on an exact
flag match, or the `=`-suffix value. It never tracks tokens already consumed as another option's
value, so a token passed as the value of `-t` is still matched later as a flag in its own right.

Reachable from untrusted input: `src/claude-hook.ts:103` builds
`[cliScript, "dispatch", "--next-command", "-t", task, …]` where `task` is the Agent prompt. A
prompt of `--exhausted=codex` is returned by `argValue("--exhausted")` and mutates dispatch state;
`--config=<path>` is returned by `resolveConfigPath()` and changes which routing document is loaded
before the command is rendered.

⚠ **Bound the severity correctly:** the call is `execFileSync(nodeBin, args)` with an argument
**array** — no shell, no command injection. This is confusion inside our own argument parser, not
arbitrary execution. The audit report does not draw that line.

Fix shape: consume value tokens during the scan (single pass that knows which flags take values),
rather than N independent global rescans.

### 2. `DEFAULT_DESTRUCTIVE` omits the Codex mutation tools

`src/config.ts:553-570`. The list covers Claude Code's harness tools — `Bash`, `BashOutput`,
`Write`, `Edit`, `MultiEdit`, `NotebookEdit` — plus conventional names, and matching is exact.
It contains neither `shell_command` nor `apply_patch`. `src/routes/admin.ts:55,69` advertises
`shell_type: "shell_command"` and `apply_patch_tool_type: "freeform"`.

`CLAUDE.md` justifies the list by "the harness's own tools", but Codex is a first-class client here,
so the "never fabricate a destructive call" guard covers one client's mutation tools and not the
other's. Same *shape* of gap as the pre-0.x fragment-matching bug that guard already learned from.

⚠ The audit's evidence is **client capability metadata**, not proof that a tool literally named
`shell_command` arrives in a request's `tools` array and reaches `repair()`. The gap is worth
closing on principle; the end-to-end path was not demonstrated.

### 3. The ping probe follows redirects while carrying a credential

`src/ping/ping.ts:117-122`. `fetch` is called with no `redirect` option, so the default
`redirect: "follow"` applies while auth headers are attached.

The Fetch spec strips `Authorization` on a cross-origin redirect but does **not** strip custom
headers, so the exposure is specific to providers authenticating with `x-api-key`. Confined to the
background health-probe path, not the request path.

Fix shape: `redirect: "manual"` (or `"error"`) on the probe fetch — a probe has no legitimate reason
to follow a redirect to another origin.

### 4. `winenv` scope merge is case-sensitive on a case-insensitive platform

`src/winenv.ts:94-105`. Scopes are merged with an object spread, which is case-sensitive, so
`PROVIDER_KEY` (Machine) and `Provider_Key` (User) survive as two distinct keys in insertion order —
Machine first. The presence check at line 100 reads `env[name]`, and **`process.env` is
case-insensitive on Windows**. Machine is therefore written first and the User entry is then seen as
already present and skipped — inverting the "User wins on a conflict" contract stated in the comment
on line 93.

⚠ **Why the suite cannot catch it as written:** `recoverWindowsEnv` takes `env` as an injectable
parameter, and a plain JS object *is* case-sensitive, so an injected env makes the bug disappear.
A regression test has to exercise case-insensitive lookup explicitly.

Requires the two scopes to spell one variable differently, so likelihood is low — but a credential
is exactly the kind of variable this function exists to recover.

## Audit-process defects worth knowing

Recorded in `.audit-tools/audit-friction-run.json`. Two matter if this is run again:

- The `free_form_intent` clause splitter fragments on punctuation and then **blocks planning on the
  fragments it created** — one clause was half a parenthetical, another a sentence cut at its first
  comma. Costs a full confirm-intent re-loop.
- The systemic-challenge lane is never told that an empty result terminates its own loop, nor that
  prior rounds exist as a dedup baseline. Left alone it padded: rounds returned 5, 5, 6. After
  explicit anti-padding instructions were written into the dispatch it returned 0. **The host has to
  supply the convergence condition the tool owns.**
